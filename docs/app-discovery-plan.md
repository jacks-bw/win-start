# 程序发现方案改进计划：补齐 UWP / Microsoft Store 应用

> 历史设计记录：下文描述旧 Electron 扫描器及当时采样数据，不代表当前实现。当前使用 src-tauri/src/scanner.rs 扫描快捷方式和 Get-StartApps；类型区分 win32/packaged/shell，并保留历史入口 ID，详见 [daily-actions.md](daily-actions.md) 和 [recent-apps.md](recent-apps.md)。

## 背景与现状

当前程序列表的发现逻辑在 `src/main/scanner.ts`：

1. 递归扫描两个目录下的 `*.lnk` 快捷方式：
   - `%APPDATA%\Microsoft\Windows\Start Menu\Programs`（当前用户）
   - `%PROGRAMDATA%\Microsoft\Windows\Start Menu\Programs`（系统级）
2. 用正则在 `.lnk` 二进制字节流里粗略匹配目标 exe 路径
3. 按名称去重 → 中文转拼音首字母分组 → 排序

### 实测数据（本机）

| 来源 | 数量 |
|---|---|
| 文件系统 .lnk 扫描结果 | 25（用户）+ 96（系统）= 121 |
| Windows 开始菜单实际可见的全部应用（`shell:AppsFolder` / `Get-StartApps`） | 163 |

差额约 40 个应用对当前方案不可见，典型如计算器：

```
名称: 计算器
AppID: Microsoft.WindowsCalculator_8wekyb3d8bbwe!App
```

### 漏检根因

**UWP / Microsoft Store 应用没有 .lnk 文件。** 它们注册在系统 AppX 仓库中，Windows 开始菜单通过 Shell 的 `AppsFolder` 枚举它们，不会出现在 `Start Menu\Programs` 目录下。已确认本机 `%LOCALAPPDATA%\Microsoft\Windows\Application Shortcuts` 为空，没有可扫的捷径文件。

## 方案

保留现有 .lnk 扫描（Win32 老程序入口），叠加一层 UWP 枚举。

### 1. 枚举：主进程调用 PowerShell `Get-StartApps`

```powershell
Get-StartApps | Select-Object Name, AppID | ConvertTo-Json -Compress
```

返回全部 `名称 + AppID`，与系统开始菜单完全一致。

### 2. 筛选：只补 UWP 条目

`Get-StartApps` 同时包含 Win32（即 .lnk 扫描已覆盖的）和 UWP。区分规则：

- **UWP AppID 必然包含 `!`**（格式：`PackageFamilyName!ApplicationId`，如 `Microsoft.WindowsCalculator_8wekyb3d8bbwe!App`）
- Win32 条目的 AppID 是注册的 AUMID 或自动生成的 GUID（`Microsoft.AutoGenerated.{...}`），不含 `!`

筛选条件：`AppID 包含 !` → 视为 UWP 新条目，与现有 .lnk 列表按名称去重后合并。

### 3. 启动方式

Win32 保持现状（`shell.openPath(lnkPath)`）。

UWP 新增启动路径：

```typescript
// explorer.exe shell:AppsFolder\<AppID>
exec(`explorer.exe shell:AppsFolder\\${appId}`)
```

`AppItem` 结构扩展：

```ts
{
  id: string          // md5(AppID)，保证稳定
  name: string
  lnkPath: string     // UWP 为空
  targetPath: string  // UWP 为空
  uwp?: boolean       // 标记
  uwpAppId?: string   // shell:AppsFolder 用
  ...
}
```

`launcher.ts` 的 `launchApp` 增加分支：`uwp` → explorer shell 协议。

### 4. 图标（v1 用占位，不阻塞）

现状确认：`extract-file-icon` 依赖已安装但**从未被调用**，当前所有应用的 `icon` 都是空串，列表统一显示占位图标。因此：

- UWP 条目 v1 同样使用占位图标，**无体验回退**
- 后续增强（可选）：批量 PowerShell 读取 AppX manifest 中的 Logo 路径，或走 `Get-AppxPackage` + `Get-AppxPackageManifest`，在枚举阶段一次取回图标文件路径，渲染层用 `file://` 展示

### 5. 刷新时机

- 启动时扫描一次，结果缓存
- 已有的 `onAppsChanged`（远端新增的目录监听事件）触发时重新枚举

### 6. 右键菜单功能降级

UWP 条目没有 `lnkPath`，以下功能在右键菜单中隐藏/禁用：

- 显示文件所在位置（showInFolder）
- 固定到任务栏
- 卸载（或改为 `ms-settings:appsfeatures`）

其余（重命名分组、固定到开始菜单）不受影响。

## 可行性评估

| 事项 | 评估 |
|---|---|
| `Get-StartApps` 枚举 | 成熟 API，PowerShell 一条命令返回 JSON，风险低 |
| UWP 启动 | `explorer.exe shell:AppsFolder\<AppID>` 是官方激活方式，风险低 |
| 性能 | PowerShell 冷启动约 300~500ms，启动时一次性调用 + 缓存，可接受 |
| 图标 | v1 占位，与现有 Win32 表现一致，无回退 |
| 去重 | `!` 启发式可靠（UWP AUMID 必有 `!`），再按名称二次去重 |
| 排序/搜索/拼音 | 复用现有 pipeline，名称来自系统本地化显示名，pinyin 分组逻辑不变 |

## 需要补充/注意的点

1. **`Get-StartApps` 会混入一些不想展示的条目**：如 `计算机管理`（`Microsoft.AutoGenerated.{...}` 类控制项捷径）、URL 类条目。需要一份过滤规则（按 AppID 前缀或名称黑名单），避免列表里出现"计算机管理""关于 Windows"这类系统项。
2. **右键菜单降级逻辑**要改 `AppContextMenu.vue`，不能只改数据层。
3. **已固定（pinned）/最近添加（recentApps）**按 id 存取，UWP 用 md5(AppID) 即可兼容，无需迁移数据。
4. **现有 .lnk 正则解析是另一个已知缺陷**（中文路径/参数可能匹配错目标），本次不动，但建议后续换正经的 lnk 解析（如 `node-lnk` 或直接走 IShellLink COM）。
5. **权限**：`Get-StartApps` 无需管理员权限。
6. **失败兜底**：PowerShell 调用失败时降级为现有 .lnk 扫描，不阻塞菜单打开。
