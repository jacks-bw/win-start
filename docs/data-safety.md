# 扫描与布局数据保护

## 应用扫描（A7）

- Rust 返回 `apps / complete / warnings`，PowerShell 启动失败、非零退出、JSON 不完整及目录读取异常不再等价于扫描成功。
- 部分扫描只添加和更新已发现应用；失败时保留上次列表。完整扫描可以更新应用列表，但任何扫描均不自动删除用户磁贴或固定状态。
- 卸载后留下的磁贴需用户手动取消固定。应用不在列表中只能说明本次未发现，不能作为删除布局的依据。
- 重扫后重新应用已保存的文件夹归属和本次运行内的固定状态，避免扫描默认字段清空用户元数据。

## 布局编辑（A8）

- 磁贴样式和分组背景使用独立草稿，控件操作不自动写布局；确定时提交，取消或直接关闭不回写旧快照。
- 独立窗口不再同时运行主菜单的初始化和布局刷新监听，防止父组件加载覆盖子组件草稿。
- 每次提交包含读取时的原始布局和当前草稿。Rust 在锁内读取最新文件，按分组 ID、磁贴 ID 和字段合并变更。
- 不同字段可以合并；同一字段的不同修改、编辑目标已被删除、删除目标已被其他窗口修改，均拒绝本次提交。
- 冲突时保留当前草稿并显示错误，不自动关闭窗口或覆盖文件；可取消后重新打开编辑。普通主窗口也显示保存错误，只有用户明确选择重新载入才丢弃未保存内容。
- 同一窗口的自动保存串行并合并后续请求；刷新响应不能覆盖请求发出后的新修改。
- 多个编辑窗口同时存在时，关闭其中一个不会解除其余窗口的主菜单锁定。

布局仍保存在原 `tile-layout.json`，不需要迁移文件格式。加载时区分文件不存在、读取失败及内容损坏；后两者不回退为空布局后继续保存。
保存时先写同目录临时文件并同步，再使用 Windows 文件替换操作更新目标。写入或替换失败时保留原文件。
锁用于同一应用进程内的多个窗口；本轮未引入多个应用实例之间的文件事务锁。
取消草稿不会清理已导入但未引用的背景图片文件，本轮只保护布局提交和取消语义。

## 验证

- `npm run test:data`：9 项前端测试，使用实际 Pinia store 和模拟桌面 API，覆盖部分/失败扫描、文件夹恢复、草稿取消、提交、保存串行、冲突保留和过期刷新。
- `cargo test --offline`：18 项 Rust 测试，其中 8 项布局测试、3 项扫描测试、7 项已有全屏测试。
- 布局文件测试实际执行临时文件读写、合并、冲突拒绝、损坏文件保护，并用禁止删除共享的文件句柄模拟替换失败。
- TypeScript 检查及 Vite 构建。

尚需桌面交互验收：同时打开磁贴样式和分组背景，分别保存/取消；修改同一磁贴背景确认冲突；模拟扫描失败后重开菜单，检查磁贴仍保留。
