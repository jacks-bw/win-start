# 快捷键修改与失败回滚（A9）

修改快捷键不再使用 `unregister_all()`：

1. 先解析目标快捷键；输入无效时不修改任何注册或配置。
2. 新旧快捷键不同且新键未注册时，先注册新键。被其他程序占用时直接失败，旧键保持不变。
3. 新键可用后才注销本应用原来生效的旧键，其他快捷键注册不受影响。
4. 使用同目录临时文件、同步和 Windows 文件替换保存配置。
5. 只有以上步骤全部成功才更新内存设置。

旧键注销或文件保存失败时，尝试先恢复旧键，再移除本次新增的键；不清理操作前就已经注册的键。
重复保存相同快捷键不注销重注册；空字符串代表禁用，禁用失败时也恢复旧键。
如果启动时原快捷键已经注册失败，不会把它当作当前生效的键错误注销。

系统注册和文件写入无法组成一个操作系统级原子事务。极端情况下，其他程序抢占刚释放的旧键，
或者系统拒绝注销新键，回滚也可能失败。错误会明确报告哪一步未恢复，并提示通过托盘重新设置，
不会声称原快捷键一定已经恢复。磁盘配置在原子替换失败时保持原文件，内存设置不提交。

`storage.rs` 的原子 JSON 写入也由布局保存复用；设置文件不再使用直接截断覆盖。
这不代表所有其他设置的内存更新都具备事务回滚，本轮只修改快捷键提交顺序。

设置界面和旧快捷键窗口在保存期间禁用重复操作，使用提交时的快照更新成功状态；失败时保留待修改输入并显示错误。

## 验证

11 项快捷键事务测试使用模拟注册器，不占用或修改真实系统快捷键，覆盖输入无效、占用、注册顺序、
保存失败、注销失败、相同快捷键、禁用回滚、原键未注册、回滚失败及已有注册保留。
29 项 Rust 测试（含上述 11 项）、10 项桥接测试、9 项数据测试、TypeScript 检查及前后端构建通过。
共享文件写入实现还由布局文件测试验证文件被占用时保留原文件。

仍需桌面验收：尝试被其他程序占用的组合键，确认保存报错后原键仍能打开菜单；
正常修改和重置后确认仅目标键生效，并在重启后保持设置。
