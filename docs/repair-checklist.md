## 热区焦点专项（优先处理）

### H1 [高优先级，待复现] 点击热区关闭菜单存在失焦与切换竞争

- 位置：launch_button.rs 的 create_button、btn_proc / WM_LBUTTONUP、toggle_menu；main.rs 的主窗口 Focused(false) 回调。
- 当前热区不带 WS_EX_NOACTIVATE，也没有处理 WM_MOUSEACTIVATE，普通点击可以先激活热区。
- 主菜单失焦时立即发送 menu-close 并 hide；热区在鼠标松开后才检查 is_visible 决定开关。
- 可能顺序：菜单可见 → 按下热区 → 热区激活、菜单失焦隐藏 → 松开热区 → is_visible 为 false → 再次打开菜单。
- 热区在独立线程，主菜单在 Tauri 线程，两侧消息处理顺序不能假定一致。
- 验证：同屏打开后再点一次，分别快速点击、按住 1 秒后松开；记录主菜单失焦/隐藏、热区激活/松开、toggle_menu 决策顺序。跨屏点击也要验证。
- 修复方向：先明确普通模式是否必须激活热区。若无必要，普通模式阻止鼠标激活、编辑模式允许激活；若需要激活，则统一管理点击意图与失焦隐藏，不能在松开时仅凭可见性反推意图。
- 验收：同屏单击可靠切换开关；跨屏点击移动菜单；外部点击仍正常隐藏。

### H2 [中优先级，代码确认；效果待复现] 失焦置顶并非通用遮挡通知

- 位置：btn_proc / WM_ACTIVATE。
- WA_INACTIVE 仅在热区激活状态发生变化时触发。热区未激活期间，其他窗口的 Z 序变化不必触发该消息。
- 因此本次改动可补充“热区失活时置顶”，不能据此认定任务栏压住热区的问题已解决；仍依赖 WM_WINDOWPOSCHANGING 和每秒自愈。
- 验证：未点击热区时反复点击任务栏、显示桌面、切换应用，检查是否出现最多约 1 秒不可点击窗口期。
- 修复方向：将置顶维护与键盘焦点需求分开评估；依据实际遮挡事件选用机制，避免仅为获取失焦事件而引入激活副作用。

### H3 [高优先级，代码确认；交互影响待复现] 热区绕过设置预览交互锁

- 位置：toggle_menu；main.rs / MENU_BLOCKED。
- 设置与样式窗口会锁定主菜单、阻止失焦隐藏，但 toggle_menu 不检查锁定状态。
- 点击热区仍可隐藏或移动主菜单；热区可激活后，还可能把焦点从设置窗口移走。
- 验证：分别打开设置、头像、磁贴样式、分组背景后点击同屏及另一屏热区。
- 修复方向：为菜单所有入口定义一致的锁定策略；锁定时忽略切换，或聚焦正在编辑的窗口。

### H4 [中优先级，代码确认] 热区关闭路径未统一发送 menu-close

- 位置：toggle_menu 同屏关闭分支；类似情况还存在于托盘和全局快捷键关闭分支。
- 分支直接 hide，没有显式 menu-close；若失焦回调未提供兜底，前端临时对话框、右键菜单、刷新计时器可能不及时清理。
- 验证：打开右键菜单/对话框后通过各入口关闭，再打开检查残留。
- 修复方向：统一关闭入口，确保状态和前端通知同步，避免依赖附带的焦点事件。

### H5 [中优先级，待复现] 焦点变化与全屏穿透存在采样窗口

- 位置：fullscreen_devices、tick_buttons、heal_one、btn_proc / WM_ACTIVATE。
- 全屏检测每秒采样当前前台窗口，热区自身或主程序窗口前台时返回空集合。
- 全屏刚进入、尚未采样时，热区可能仍可点并激活，进而影响下一次全屏判断。
- WM_ACTIVATE 分支会避开已穿透窗口，但 heal_one 在普通模式下仍对穿透窗口调用 HWND_TOPMOST；这与允许全屏程序覆盖它的注释需要一起核对。
- 验证：F11、无边框游戏、独占全屏进出瞬间，结合主副屏、任务栏自动隐藏检查点击与焦点。
- 验收：全屏所在屏幕不被热区截获点击，其他屏热区仍可用；退出全屏后正常恢复。

## 热区专项建议验证顺序

1. 优先复现 H1，确认普通点击是否应允许热区激活。
2. 检查编辑模式拖动、缩放、方向键、Shift 加速、Esc 与失焦取消选择。
3. 验证设置锁定 H3 和关闭通知 H4。
4. 最后覆盖任务栏、Win+D、Alt+Tab、多屏/DPI、全屏进出 H2/H5。

建议日志字段：时间、线程、HWND、消息、前台 HWND、主菜单可见性、编辑模式、锁定状态、穿透状态和切换决策。
仅在复现阶段临时记录关键事件，避免对高频绘制和窗口位置消息持续刷日志。

## Windows 行为依据

- WM_MOUSEACTIVATE / MA_NOACTIVATE：可以保留鼠标消息而不激活窗口。https://learn.microsoft.com/en-us/windows/win32/inputdev/wm-mouseactivate
- WM_ACTIVATE：不同输入队列的激活通知是异步的。https://learn.microsoft.com/en-us/windows/win32/inputdev/wm-activate
- SetWindowPos / SWP_NOACTIVATE：调整 Z 序可不激活窗口。https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos
