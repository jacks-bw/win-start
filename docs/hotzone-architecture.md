# 热区控制实现与验收

## 控制逻辑

- `launch_button.rs`：单个原生线程管理所有显示器热区及隐藏控制窗口。
- `fullscreen.rs`：枚举顶层窗口，按显示器判断全屏；忽略本程序、桌面、任务栏、最小化和 cloaked 窗口。
- `main.rs`：热区、托盘、快捷键通过主线程统一切换主菜单，检查预览锁定，并在关闭时发送 `menu-close`。

正常热区使用 `WS_EX_NOACTIVATE`，并通过 `WM_MOUSEACTIVATE / MA_NOACTIVATE` 保留点击、不抢焦点。
按下和松开时重新检查全屏；鼠标捕获与释放检查避免按下后拖出热区仍触发切换。
同屏点击关闭，跨屏点击移动菜单。定位限制在工作区，菜单大于工作区时不会发生 clamp 区间反转。

每个显示器保存自己的暂停状态。全屏时热区隐藏且设置鼠标穿透，暂停置顶；退出后恢复。
编辑模式显式覆盖全屏暂停，允许焦点及原有拖动、缩放、方向键操作。
不再拦截所有隐藏请求，不再依赖热区失焦来维护置顶。

使用进程外 WinEvent 监听前台、窗口显示隐藏、层级、位置、最小化和 cloaked 状态变化。
回调不直接操作窗口，合并通知后通过 20ms 定时器刷新，过滤本进程事件避免自身置顶反馈。
每秒巡检补漏。隐藏控制窗口为顶层窗口，接收显示器、工作区及 `TaskbarCreated` 广播。
所有屏幕都在每轮刷新中独立应用状态，不能因只有主屏获得前台事件而遗漏副屏。

屏幕位置和 DPI 变化时按旧屏幕原点及 DPI 比例迁移热区；兼容原 `launch-buttons.json`。
新增屏幕的默认热区放在屏幕任务栏边缘，实际开始按钮位置仍可在编辑模式调整，
不会自动识别 Windows 11 居中开始按钮。

## 全屏判定策略及边界

几何判定使用 DWM 实际窗口边界，失败时退回 GetWindowRect。无系统标题栏/缩放边框，
且覆盖整个显示器（允许 2 个物理像素误差）时判为全屏。普通有边框最大化不算全屏。
按窗口层级检查：上方普通窗口覆盖至少该屏 25% 时，视为已经返回桌面使用；小型控件与
不激活/工具浮层不会清除下方全屏状态。这个 25% 是交互策略，并非 Windows 全屏标准。
独占 Direct3D 的 Shell 状态仅补充前台所在显示器，不用它替代多屏几何判断。
窗口枚举失败时保留上一状态，并拒绝本次热区点击。

无边框最大化与真全屏在部分软件中无法仅凭窗口样式区分，特殊游戏/外壳仍需实机验证。
正常置顶采用公开 Win32 API，没有使用未公开 Z-order band、Explorer 注入或全局鼠标拦截。
不能保证普通窗口绝对压过任何系统层级；事件响应也不是零延迟。

## 验证

自动检查：`cargo check --offline`、`cargo test --offline`、`npm run build`。
7 项单元测试覆盖：副屏全屏与主屏前台独立、有边框最大化、普通窗口遮挡、
小型控制条、不激活浮层、负坐标跨屏、几何误差及工作区大小。

桌面验收尚未执行，建议依次进行：

1. 每个屏幕点击热区打开、再点击关闭；按住 1 秒再松开；拖出再松开不触发。
2. 主屏打开后点击副屏热区，菜单移动至副屏且搜索框可输入。
3. 分别点击每屏任务栏、Alt+Tab、Win+D，确认热区保持可点击。
4. 副屏浏览器 F11 或视频全屏，在主屏操作普通窗口；副屏热区不拦截，主屏仍可用。
5. 退出/最小化/关闭全屏窗口后确认热区恢复；覆盖真实无边框游戏及独占游戏。
6. 打开设置和样式窗口后点热区，不隐藏或移动已锁定的菜单。
7. 编辑模式拖动、缩放、方向键、Shift 加速、Esc；退出后点击不抢焦点。
8. 改变 DPI、屏幕排列，插拔副屏，重启 Explorer，检查各屏位置与点击能力。

构建与单元测试通过不代表上述桌面交互已经验收。
